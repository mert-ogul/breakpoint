# Saved results of the Diffusion PushT stress benchmark

Saved results of the exploratory run: Diffusion Policy on PushT, simulation only. The report is at [`report/report.md`](report/report.md). `report/index.html` is the interactive version; open it from a local copy. To rebuild it from this data, follow the [README quickstart](../../../README.md#render-the-saved-report) with `--input benchmarks/diffusion-pusht/stress/data`. To repeat the run, see [docs/reproduce.md](../../../docs/reproduce.md#diffusion-policy-on-pusht). The rules behind the numbers are in [docs/methodology.md](../../../docs/methodology.md#diffusion-policy-on-pusht).

## Layout

| Path | Contents |
| --- | --- |
| `report/` | `index.html`, `report.md`, SVG and PNG plots, `data_index.json` (generated by `scripts/render_benchmark.py`) |
| `data/episodes/episodes.jsonl` | One compact record per episode and condition (80 rows). Each row's `source_report` names the raw source |
| `data/summaries/` | Saved experiment summaries, verbatim (three axes) |
| `data/protocol/` | Config, protocol lock, run records and the three experiment plans, verbatim |
| `data/identities/`, `data/validation/` | Checkpoint hashes, export manifest, upstream agreement |
| `data/timing/` | Packaged laptop-m3 action-generation timing profile |
| `data/historical/` | Per-condition provenance and planned settings, verbatim |
| `data/large_evidence.json` | Size and SHA-256 of evidence that is not in the repository |
| `data/manifest.json` | SHA-256 of every packaged file |

Episode records keep outcome, seeds, step and inference counts, reward sums, image settings and `source_report`. Per-step actions and observations are not copied.

## Result-specific limitations

- Exploratory run, 5 episodes per condition; not confirmed with fresh seeds. An interval that spans the threshold is unresolved.
- No runtime errors or policy failures; every non-success is a time-limit truncation (46 success, 34 time_limit_truncation in 80 rows).
- Model card success is 65.4% over 500 episodes; this run's baseline is 5/5. Stated as context, not a reproduction.
- Delay is injected in simulated time; host generation time is not added.
- No ONNX, quantization, H.264 or device replay for this candidate ([methodology](../../../docs/methodology.md#diffusion-policy-on-pusht)).
- The saved resolution summary used the same ordered value for every point; the report orders by plan (96x96 native, 48x48, 32x32, 24x24).
- Other tasks, policies, physical hardware, and transfer of these thresholds to another setup are not covered.

## Evidence that is not in the repository

The control-step logs are in the original run directory, which git ignores: `outputs/diffusion-pusht/full/axes/*/conditions/*/run_report.json` and `outputs/diffusion-pusht/full/shared_baselines/default_fp32_native_L0/run_report.json` (about 18 MB). The `episodes.jsonl` files beside them duplicate the same episodes and add about 12 MB. The timing profile samples are under `profiles/laptop-m3/diffusion_pusht`. Sizes and hashes are in `data/large_evidence.json`. The verbatim protocol, summary and provenance files keep absolute paths from the machine that produced them; they identify the source and are not links. Every link in the report and in this directory is relative.

Historical provenance paths under `data/historical/` name the source conditions for `v0.1_full_latency`, `v0.1_full_resolution`, `v0.1_full_jpeg` and `shared_baselines`.

To package these logs again, pass the locations explicitly. The package is written outside the repository evidence:

```bash
.venv/bin/python scripts/package_benchmark.py \
  --input outputs/diffusion-pusht/full --export-dir artifacts/export/diffusion_pusht --out /tmp/breakpoint-pusht-package
```
